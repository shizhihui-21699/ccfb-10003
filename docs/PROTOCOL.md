# TLVX 二进制协议规范 v1

本文档定义 `libtlv` 解析/编码的线格式。实现必须与本文档逐条对应；`tests/` 中的
一致性用例即为规范的可执行版本。

## 1. 术语

| 术语 | 含义 |
|------|------|
| 消息 (message) | 一个完整的字节序列，由 11 字节固定头 + 字段区组成 |
| 作用域 (scope) | 一段字段序列。根消息本身是一个作用域；每个容器类型的值也是一个作用域 |
| 标签 (tag) | 无符号变长整数，在同一作用域内标识字段 |
| 容器 (container) | 类型为 `CONTAINER` 的字段，其值本身是「存在位图 + 字段序列」 |
| 存在位图 (presence bitmap) | 每个作用域开头 1 字节，bit *i* = 1 表示可选槽位 *i* 的字段存在 |

所有多字节整数一律 **大端 (big-endian)**，除显式标注为 LEB128 的变长整数外。

## 2. 消息结构

```
+--------+---------+---------+------------------+---------------------------+
| magic  | version | flags   | field_region_len | field region              |
| 4 B    | 1 B     | 2 B BE  | 4 B BE           | field_region_len 字节      |
| "TLVX" | 0x01    |         |                  | 存在位图(1B) + 字段序列    |
+--------+---------+---------+------------------+---------------------------+
```

- `magic` = `0x54 0x4C 0x56 0x58`（ASCII `TLVX`）。
- `version` 必须为 `0x01`。其它版本 → `TLV_ERR_BAD_VERSION`。
- `flags`：bit0 = `STRICT`（见 §7）。bit1..15 为保留位，**必须为 0**，否则
  `TLV_ERR_BAD_FLAGS`。
- `field_region_len`：字段区的字节数，**包含**字段区开头的存在位图字节。
  因此整条消息长度 = `11 + field_region_len`。
  - 严格模式（`flags.STRICT=1` 或 `tlv_options.strict=1`）要求输入缓冲区长度
    **恰好**等于 `11 + field_region_len`，否则 `TLV_ERR_LENGTH_MISMATCH`。
  - 宽松模式下允许尾部多余字节，解析器忽略它们。
- `field_region_len` 必须 ≥ 1（至少要有一个存在位图字节），否则
  `TLV_ERR_TRUNCATED`。
- 输入总长度 > `options.max_message_bytes`（默认 16 MiB）→ `TLV_ERR_LIMIT`。

## 3. 字段结构

```
+-----------+------------+--------------+-------------------+
| tag       | type byte  | length field | value             |
| LEB128    | 1 B        | 1..6 B       | 由 length 指定     |
+-----------+------------+--------------+-------------------+
```

### 3.1 标签 tag

- 无符号 LEB128（§4.1），最多 5 字节，取值范围 `1 .. 0xFFFFFFFF`。
- 保留值 `0` → `TLV_ERR_BAD_TAG`。
- **同一作用域内标签必须严格递增**，否则 `TLV_ERR_TAG_ORDER`。
- 非规范（多余前导 0x00 字节）形式在严格模式下 → `TLV_ERR_VARINT`。

### 3.2 类型字节

```
bit 7   6 5 4   3      2 1 0
 C  |  kind  |  O  |  slot  |
```

- `kind`（bit 6..4）：

  | 值 | 名称 | 值内容 |
  |----|------|--------|
  | 0 | INT | 有符号 LEB128，1..8 字节（值域 ±(2^55-1)） |
  | 1 | UINT | 无符号 LEB128，1..8 字节（值域 0..2^56-1） |
  | 2 | BYTES | 任意字节序列 |
  | 3 | STRING | UTF-8 文本（严格校验，见 §5.4） |
  | 4 | BOOL | 恰好 1 字节，值 0 或 1 |
  | 5 | CONTAINER | 嵌套作用域（必须同时置 C 位） |
  | 6 | SKIP | 任意字节，解析器不解释（前向兼容） |
  | 7 | 保留 | → `TLV_ERR_RESERVED_KIND` |

- `C`（bit 7）：构造位。`C=1` 时 `kind` 必须为 5，否则 `TLV_ERR_BAD_TYPE`；
  `kind=5` 时 `C` 必须为 1，否则同样报错。
- `O`（bit 3）：可选位。`O=1` 表示该字段是可选字段，占用 `slot` 指定的存在槽位。
  其值为 1 时，当前作用域的存在位图中对应 bit **必须**为 1，否则
  `TLV_ERR_BAD_OPTIONAL`；同一槽位在一个作用域内只能被声明一次
  （重复 → `TLV_ERR_BAD_OPTIONAL`）。
- `O=0` 时 `slot` 三位必须为 0，否则 `TLV_ERR_BAD_TYPE`。
- 作用域结束时，存在位图中为 1 但没有任何可选字段声明使用的位 →
  `TLV_ERR_OPTIONAL_UNUSED`（严格模式）。

### 3.3 长度字段

首个字节 `b0` 决定编码形式：

| 条件 | 形式 | 长度范围 |
|------|------|----------|
| `b0 & 0x80 == 0` | 单字节，`len = b0` | 0 .. 127 |
| `b0 & 0xE0 == 0x80` | 双字节，`len = ((b0 & 0x1F) << 8) \| b1` | 0 .. 8191 |
| `b0 & 0xF0 == 0xC0` | 三字节，`len = ((b0 & 0x0F) << 16) \| (b1 << 8) \| b2` | 0 .. 1048575 |
| `b0 == 0xE0` | 其后跟无符号 LEB128（最多 5 字节），`len = varint` | 0 .. 0xFFFFFFFF |
| `0xD0..0xDF` 或 `0xF0..0xFF` | 保留 | → `TLV_ERR_BAD_LENGTH_ENCODING` |

注意各形式的判定区间互不重叠：`0x80..0x9F`、`0xC0..0xCF`、`0xE0`、
`0xD0..0xDF` 与 `0xF0..0xFF` 为保留区间。

- 长度字段本身（含 `0xE0` 前缀）不计入 `len`。
- `len` 不得超出当前作用域剩余字节数，否则 `TLV_ERR_TRUNCATED`。
- 变长形式的 `len` 在严格模式下要求规范 LEB128 编码（末字节非 0 且无多余字节）。

### 3.4 值约束

- **INT**：1..8 字节有符号 LEB128，解码结果落在 int64 内。编码必须**恰好**
  消耗 `len` 字节（提前终止 → `TLV_ERR_VALUE`），`len == 0` → `TLV_ERR_VALUE`。
  规范形式判定见 §4.2；非规范 → `TLV_ERR_VARINT`（严格模式）。
- **UINT**：1..8 字节无符号 LEB128，同样要求恰好消耗 `len` 字节；
  规范形式见 §4.1。
- **BOOL**：`len` 必须为 1 且值 ∈ {0, 1}，否则 `TLV_ERR_VALUE`。
- **STRING**：按 §5.4 校验 UTF-8，失败 → `TLV_ERR_UTF8`。
- **CONTAINER**：`len` ≥ 1（第一个字节是子作用域的存在位图）。
- **BYTES / SKIP**：无约束。

## 4. 变长整数（LEB128）

### 4.1 无符号 LEB128

每字节低 7 位为数据，bit7 为延续位。受字段长度约束，最多 8 字节
（56 位数据，值域 0..2^56-1）。

规范形式：`n > 1` 时，末字节的 7 位数据**不得为 0**（否则可更短表示）。
违反 → 严格模式 `TLV_ERR_VARINT`。

### 4.2 有符号 LEB128

同 ULEB128 的字节结构，最高有效字节的 bit6 是符号位，解码后按该位
向高位符号扩展。最多 8 字节，因此值域为 ±(2^55-1)，结果类型为 int64。

规范形式：`n > 1` 时，设末字节 7 位数据为 `p`、前一字节原始值为 `prev`：

- `p == 0x00` 且 `(prev & 0x40) == 0` → 非规范（正数前导零）；
- `p == 0x7F` 且 `(prev & 0x40) != 0` → 非规范（负数前导 1）。

反例：`-1` 只能是单字节 `0x7F`；`0xBF 0x7F` 表示 `-65`，是规范的。

### 4.3 字节数上限

任一 LEB128 序列在达到最大字节数后仍带延续位 → `TLV_ERR_VARINT`；
中途越过当前作用域边界 → `TLV_ERR_TRUNCATED`。

## 5. 作用域与嵌套

### 5.1 作用域开头

每个作用域（根消息字段区、每个容器的值）的第一个字节都是 1 字节存在位图。
该字节计入所属的长度 / `field_region_len`。

### 5.2 嵌套深度

- 根作用域算作深度 0；根的直接子字段深度 1；容器内字段深度 = 容器深度 + 1。
- `max_depth` 限制的是**容器嵌套层数**：第 `k` 层容器（根的直接子容器为第 1 层）
  允许当且仅当 `k <= max_depth`（默认为 16，硬上限 64）。超限 → `TLV_ERR_DEPTH`。
  因此最内层容器里的叶子字段其 `node.depth` 可达 `max_depth + 1`，这是规范的，
  不视为越限。
- 该检查在**进入**容器之前进行，所以恶意深嵌套会在压栈前被拒绝，解析器栈溢出
  不可能发生。
- 解析器实现为**迭代式**（显式作用域栈，容量 `max_depth + 2` 帧），全程无递归。

### 5.3 作用域完整性

- 容器的字段序列必须恰好填满其 `len - 1` 字节（位图之后的区域），
  多一字节或少一字节 → `TLV_ERR_LENGTH_MISMATCH`。
- 根字段区同理必须恰好填满 `field_region_len - 1` 字节。
  在宽松模式下，尾部剩余字节被忽略（见 §2）。

### 5.4 UTF-8 严格校验（RFC 3629）

拒绝以下情况（`TLV_ERR_UTF8`）：

- 孤立延续字节 `0x80..0xBF`；
- 5/6 字节序列（`0xF8..0xFF` 前导）；
- 过度长编码（overlong）：如 `0xC0 0x80` 表示 U+0000；
- UTF-16 代理区 `U+D800..U+DFFF`；
- 码点 > `U+10FFFF`；
- 序列在值边界处被截断；
- 非法延续字节、非法首字节范围。

合法的 `U+0000` 用 `0x00` 编码是允许的（与「字符串以 NUL 结尾」无关）。

## 6. 资源上限（`tlv_options`）

| 选项 | 默认 | 超限错误 |
|------|------|----------|
| `max_depth` | 16（硬上限 64） | `TLV_ERR_DEPTH` |
| `max_fields`（每作用域字段数） | 65536 | `TLV_ERR_FIELDS` |
| `max_total_fields`（整条消息字段总数） | 262144 | `TLV_ERR_FIELDS` |
| `max_message_bytes` | 16 MiB | `TLV_ERR_LIMIT` |

内存由解析器内部 arena 分配，其上限由 `max_total_fields * sizeof(node) + 4096`
推导。超限 → `TLV_ERR_NOMEM`。

## 7. 严格模式与宽松模式

- `tlv_options.strict`（默认 1）与消息头 `flags.bit0` **同时**为真时进入严格模式；
  否则为宽松模式。
- 严格模式额外要求：消息无尾部多余字节、LEB128 规范、可选位图位全部被使用。
- 宽松模式仍然执行所有**内存安全相关**的边界检查：长度不越界、深度受限、
  变长整数字节数受限。宽松只放宽「可更短编码」这类语义约束。

## 8. 解析结果模型

- 解析成功产出一棵只读树：根节点为伪节点（tag=0，kind=CONTAINER，深度 0）。
- 节点记录 `tag`、`kind`、`optional/slot`、`depth`、`offset`（tag 字节在输入中的偏移）、
  `value`（叶子的值字节指针；容器为位图字节指针）、`value_len`、子节点链表。
- **所有权**：树的所有节点由解析器 arena 持有；值字节**不复制**，直接指向调用方的
  输入缓冲区。调用方必须保证缓冲区在 `tlv_document` 存活期间有效。
- 失败时 `*out_doc` 保持 `NULL`，所有中间分配随 arena 一起释放（无泄漏、无
  部分树泄漏）。
- `tlv_document_free()` 可接受 `NULL`。

## 9. 错误码一览

见 `include/tlv.h` 中的 `tlv_error` 枚举及 `tlv_strerror()`。

## 10. 版本与兼容

- 未知 `kind=6`（SKIP）保证前向兼容：新版本新增字段类型时，旧解析器可安全跳过。
- 保留位 / 保留 kind / 保留长度形式一律报错而不是猜测，避免歧义解析。
- 未来版本升级必须改 `version` 字段；v1 解析器拒绝其它版本。
